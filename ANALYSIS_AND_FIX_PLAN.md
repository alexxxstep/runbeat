# Аналіз проблеми AI агента та план виправлення

## 🔍 Виявлені проблеми

### Основна проблема: Агент не зберігає витягнуті параметри

**Симптоми:**

- Агент повторює одне і те ж питання кілька разів
- Користувач надав інформацію (наприклад: "інтервальна на 39 хвилин під релаксну музику в стилі техно"), але агент знову питає про тривалість та інтенсивність

**Причина:**

1. Агент отримує контекст з `state.collected_parameters`, який показує, що вже зібрано
2. Агент витягує параметри з поточного повідомлення користувача (згідно з промптом)
3. **НО:** Після виклику агента `state.collected_parameters` НЕ оновлюється автоматично
4. На наступному кроці контекст все ще показує порожній або старий `collected_parameters`
5. Агент знову бачить, що параметри відсутні, і повторює питання

### Детальний аналіз коду

**Файл:** `apps/backend/app/services/workout_builder.py`

**Проблемний фрагмент (рядки 107-185):**

```python
# Add user message to history
state.history.append({"role": "user", "content": user_message})

# Build comprehensive context for the AI agent (with user patterns)
conversation_context = await self._build_conversation_context(state, user_message)

# ... виклик агента ...

# ПРОБЛЕМА: collected_parameters НЕ оновлюється після виклику агента!
# Агент витягнув параметри, але вони не збережені в state
```

**Що працює:**

- `_get_fallback_response()` (рядок 388) витягує параметри та оновлює `collected_parameters`
- Але ця функція викликається тільки при помилках або для коротких повідомлень

**Що не працює:**

- Після успішного виклику агента параметри не зберігаються в `state.collected_parameters`
- Агент базується на промпті, який каже йому витягувати параметри, але не каже, як їх зберігати

## 📋 Покроковий план виправлення

### Крок 1: Додати автоматичне витягування параметрів ПЕРЕД викликом агента

**Мета:** Оновити `collected_parameters` перед передачею контексту агенту

**Дія:**

- В `process_message()` перед викликом `_build_conversation_context()`:
  1. Витягнути параметри з поточного повідомлення користувача
  2. Витягнути параметри з останніх повідомлень користувача (якщо вони були пропущені)
  3. Оновити `state.collected_parameters` шляхом об'єднання з існуючими параметрами
  4. Передати оновлений стан до `_build_conversation_context()`

**Переваги:**

- Агент завжди бачить актуальний стан зібраних параметрів
- Контекст буде правильним з першого разу
- Зменшується кількість ітерацій агента

### Крок 2: Покращити промпт агента для кращого розуміння контексту

**Мета:** Зробити промпт більш чітким щодо використання вже зібраних параметрів

**Дія:**

- В `CONVERSATION_AGENT_SYSTEM_PROMPT`:
  1. Додати більш чіткі інструкції про те, що параметри вже витягнуті та збережені
  2. Підкреслити, що потрібно перевіряти "Already collected" перед запитанням
  3. Додати приклади, де агент бачить вже зібрані параметри та не питає повторно

**Файл:** `apps/backend/app/agents/prompts/conversation_prompts.py`

### Крок 3: Додати резервне оновлення після виклику агента

**Мета:** Забезпечити, що параметри завжди зберігаються, навіть якщо агент не виконав це явно

**Дія:**

- В `process_message()` після успішного виклику агента:
  1. Перевірити, чи були витягнуті нові параметри з поточного повідомлення
  2. Якщо так - оновити `state.collected_parameters`
  3. Це забезпечить синхронізацію стану

**Переваги:**

- Подвійна перевірка - параметри точно будуть збережені
- Захист від випадків, коли агент не виконав витягування

### Крок 4: Покращити витягування параметрів для складних випадків

**Мета:** Покращити розпізнавання параметрів у складних повідомленнях

**Приклади проблемних повідомлень:**

- "інтервальна на 39 хвилин під релаксну музику в стилі техно"
  - Треба розпізнати: type="intervals", duration=39, genres=["techno"], intensity="moderate" (default)
  - "релаксну музику в стилі техно" → techno genre

**Дія:**

- Покращити `_extract_parameters_from_user_message()`:
  1. Додати розпізнавання "релаксну музику в стилі техно" → techno
  2. Покращити розпізнавання інтенсивності для інтервальних тренувань
  3. Додати розпізнавання описових фраз про музику

### Крок 5: Додати логування для діагностики

**Мета:** Додати логування для відстеження оновлення параметрів

**Дія:**

- Додати логування:
  1. Перед витягуванням параметрів
  2. Після витягування параметрів
  3. Після оновлення `collected_parameters`
  4. Перед передачею контексту агенту

**Переваги:**

- Легше діагностувати проблеми в майбутньому
- Можна відстежити, чому параметри не оновлюються

## 🎯 Очікувані результати

Після виправлення:

1. ✅ Агент не буде повторювати питання, якщо користувач вже надав інформацію
2. ✅ `collected_parameters` завжди буде актуальним
3. ✅ Агент буде правильно розуміти контекст розмови
4. ✅ Покращиться розпізнавання параметрів у складних повідомленнях
5. ✅ Зменшиться кількість ітерацій агента

## 📝 Приклад виправлення

**До:**

```python
# Add user message to history
state.history.append({"role": "user", "content": user_message})

# Build context (collected_parameters може бути порожнім)
conversation_context = await self._build_conversation_context(state, user_message)
```

**Після:**

```python
# Add user message to history
state.history.append({"role": "user", "content": user_message})

# CRITICAL: Extract and update parameters BEFORE building context
extracted_params = self._extract_parameters_from_user_message(user_message)
# Also check recent history for missed parameters
# ... merge with existing collected_parameters ...

# Now build context with updated collected_parameters
conversation_context = await self._build_conversation_context(state, user_message)
```
