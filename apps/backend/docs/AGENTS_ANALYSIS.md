# Аналіз агентів - Перехід на AI-промпти

## Поточний стан агентів

### ✅ 1. WorkoutBuilder (services/workout_builder.py)

**Статус:** ✅ Добре реалізовано

- Використовує AI агента з детальним промптом
- Вся логіка ведення діалогу в промпті
- Код лише передає контекст та зберігає результати

**Покращення:** Мінімальні - можна додати більше інструкцій про використання інструментів

---

### ⚠️ 2. WorkoutManagerAgent (agents/manager.py)

**Статус:** ⚠️ Частково використовує промпти

**Проблеми:**

- Має промпт, але багато логіки в коді (fallback методи)
- Логіка перевірки помилок та fallback в коді (рядки 125-250)
- Перевірка iteration/time limit в коді замість промпту

**Рекомендації:**

1. **Перенести fallback логіку в промпт:**

   - Додати інструкції про обробку помилок
   - Агент має сам вирішувати, коли використовувати fallback

2. **Розширити промпт:**
   - Додати інструкції про обробку помилок від інструментів
   - Додати стратегію retry при помилках
   - Додати інструкції про перевірку існуючих воркаутів

**Код для спрощення:**

- Метод `_create_and_activate_workout_fallback` (144-250 рядки) - можна спростити або видалити, якщо агент сам обробляє помилки

---

### ⚠️ 3. MusicCuratorAgent (agents/curator.py)

**Статус:** ⚠️ Частково використовує промпти

**Проблеми:**

- Має хороший промпт, але багато логіки парсингу в коді
- Fallback методи з великою кількістю коду (247-465 рядки)
- Парсинг JSON в коді замість використання output parser

**Рекомендації:**

1. **Покращити output parser:**

   - Використовувати PydanticOutputParser більш ефективно
   - Додати інструкції в промпт про формат відповіді

2. **Спростити fallback логіку:**

   - Перенести інструкції про fallback в промпт
   - Агент має сам вирішувати, коли використовувати Spotify API напряму

3. **Розширити промпт:**
   - Додати інструкції про обробку помилок Spotify API
   - Додати стратегію retry при rate limits
   - Додати інструкції про fallback на Search API

**Код для спрощення:**

- Метод `_parse_agent_output` (190-245 рядки) - можна спростити, якщо агент правильно використовує output parser
- Метод `_create_fallback_playlist` (247-291 рядки) - можна перенести логіку в промпт
- Метод `_create_fallback_playlist_with_spotify` (293-465 рядки) - можна спростити, додавши інструкції в промпт

**Статус:** ❌ Не використовує AI агента

**Проблеми:**

- Немає промпту взагалі
- Вся логіка прийняття рішень в коді (рядки 47-75)
- Перевірка підтвердження в коді замість AI
- Створення Workout об'єкта в коді

**Рекомендації:**

1. **Створити AI агента для Supervisor:**

   - Додати промпт з інструкціями про оркестрацію розмови
   - Агент має вирішувати, коли створювати воркаут
   - Агент має обробляти підтвердження/відмову

2. **Додати інструменти:**

   - `create_workout` - для створення воркауту
   - `check_conversation_state` - для перевірки стану розмови

3. **Розширити промпт:**
   - Інструкції про коли створювати воркаут
   - Інструкції про обробку підтвердження/відмови
   - Інструкції про очищення стану

**Код для переробки:**

- Метод `handle_message` (33-80 рядки) - вся логіка має бути в промпті
- Перевірка `last_question == "final_confirmation"` - має бути в промпті
- Створення Workout об'єкта - має бути через інструмент

## Загальні рекомендації

### Принципи для всіх агентів:

1. **Вся логіка прийняття рішень в промпті:**

   - Коли використовувати інструменти
   - Як обробляти помилки
   - Коли використовувати fallback

2. **Код лише для:**

   - Передачі контексту агенту
   - Збереження результатів
   - Обробки технічних помилок (network, timeout)

3. **Промпти мають містити:**

   - Детальні інструкції про workflow
   - Приклади хороших/поганих відповідей
   - Інструкції про обробку помилок
   - Стратегії retry та fallback

4. **Інструменти:**
   - Мають бути простими та фокусованими
   - Не мають містити бізнес-логіку
   - Мають повертати чіткі результати
